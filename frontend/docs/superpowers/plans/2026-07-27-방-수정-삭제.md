# 방 수정·삭제 구현 계획

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 콘솔 대기 상태에서 눌리지 않는 "방 수정"·"방 삭제" 버튼 3개를 동작시킨다 (S15P11A704-324, S15P11A704-325).

**Architecture:** `/rooms/:id/edit` 라우트를 신설하고 `RoomCreateStep1`·`RoomCreateStep2`를 **무수정으로 재사용한 단일 폼**을 만든다. 저장은 PATCH 부분 수정이라 프리필 스냅샷과 비교해 바뀐 필드만 보낸다. 삭제는 `useRoomDelete()` composable 하나로 두 진입점이 공유한다.

**Tech Stack:** Vue 3 `<script setup lang="ts">` · vue-router · Tailwind v4 토큰 클래스 · `shared/api/rooms.ts`(axios)

**설계 근거:** `docs/superpowers/specs/2026-07-27-방-수정-삭제-design.md`

## Global Constraints

- **테스트 러너가 없다.** `vitest`·`jest` 미설치, 테스트 파일 0개. 각 태스크의 검증은 `npm run format:check` · `npm run lint` · `npm run build`(vue-tsc 타입체크 포함) **+ 브라우저 확인**이다. 테스트 코드를 새로 도입하지 않는다 — 이 레포의 게이트가 아니다.
- **색·폰트 하드코딩 금지.** `bg-surface`·`text-dim`·`border-line`·`text-terra`·`text-red` 등 토큰 클래스만. 신규 파일은 `git diff`에 안 잡히므로 `git add -A` 후 `git diff --cached`로 확인한다.
- **FE2 소유 영역 무변경:** `features/live/media/`, `features/live/socket/`, `features/chat/`, `stores/live.ts`.
- **HTTP는 `shared/api/`만 경유.** 컴포넌트에서 `axios`·`fetch` 직접 호출 금지.
- **`stores/room.ts`를 건드리지 않는다.** 그 스토어의 `createRoom`은 목 전용이고 페이로드 shape이 API 모듈과 다르다. 정리는 S15P11A704-222 몫이다.
- 커밋 제목 끝에 `(S15P11A704-324)` 또는 `(S15P11A704-325)`.
- 목 모드 기본값은 `VITE_API_MOCK=true`다. 모든 브라우저 검증은 목 모드 기준이다.

- [ ] **Step 1: `useRoomDelete.ts` 생성**

방송 종료(`ConsoleView`의 `endConfirming`)와 같은 2단계 인라인 확인이다. 5초 뒤 자동 해제하는 이유도 같다 — 확인 상태를 무기한 열어두면 한참 뒤 무심코 누른 클릭이 곧바로 삭제가 된다.

```ts
// ROOM-04 방 삭제 — 콘솔의 두 진입점(액션 줄 "방 삭제", 사이드 "방 삭제하기")이 공유한다.
// 와이어프레임도 cDropRoom·cDropRoom2가 같은 핸들러를 쓴다.
import { onUnmounted, ref } from 'vue'
import { useRouter } from 'vue-router'
import { deleteAuctionRoom } from '@/shared/api/rooms'
import { API_ERROR_CODE, hasErrorCode, toApiError } from '@/shared/api/errors'

const CONFIRM_TIMEOUT_MS = 5_000

export function useRoomDelete(auctionId: () => number) {
  const router = useRouter()
  const confirming = ref(false)
  const pending = ref(false)
  const error = ref<string | null>(null)
  let timer: ReturnType<typeof setTimeout> | null = null

  function clearTimer() {
    if (timer !== null) {
      clearTimeout(timer)
      timer = null
    }
  }

  function cancel() {
    clearTimer()
    confirming.value = false
  }

  /** 첫 호출은 확인 단계로 들어가고, 확인 중 재호출이면 실제로 지운다 */
  async function requestDelete(): Promise<void> {
    if (pending.value) return
    if (!confirming.value) {
      confirming.value = true
      error.value = null
      clearTimer()
      timer = setTimeout(() => {
        confirming.value = false
        timer = null
      }, CONFIRM_TIMEOUT_MS)
      return
    }

    cancel()
    pending.value = true
    error.value = null
    try {
      await deleteAuctionRoom(auctionId())
      // 와이어프레임 dropRoom이 go('main') — 방을 지운 판매자는 홈으로 돌아간다
      await router.replace('/')
    } catch (caught) {
      const apiError = toApiError(caught)
      if (hasErrorCode(apiError, API_ERROR_CODE.AUCTION_ALREADY_STARTED)) {
        error.value = '이미 시작된 방은 삭제할 수 없어요.'
      } else if (hasErrorCode(apiError, API_ERROR_CODE.AUCTION_HAS_PARTICIPATION)) {
        error.value = '참여자가 있어 삭제할 수 없어요.'
      } else if (hasErrorCode(apiError, API_ERROR_CODE.NOT_AUCTION_SELLER)) {
        error.value = '이 방의 판매자만 삭제할 수 있어요.'
      } else {
        error.value = apiError.message
      }
    } finally {
      pending.value = false
    }
  }

  onUnmounted(clearTimer)

  return { confirming, pending, error, requestDelete, cancel }
}
```

const imageUploading = ref(false)
const imageError = ref('')

/**
 * 이미 처리한 이미지 항목 id.
 *
 * ⚠️ 이게 없으면 **목 모드에서 무한 루프가 난다.** 목의 `uploadProductImage`는 또 다른 blob URL을
 * 돌려주므로 "blob이면 업로드한다"만으로는 종료 조건이 성립하지 않는다 —
 * 업로드 → images 변경 → watch 재발화 → 다시 blob → 업로드… 가 끝없이 돈다.
 * id 기준으로 한 번만 처리한다.
 */
const syncedImageIds = new Set<string>()

/**
 * Step1이 만든 blob 항목을 업로드 URL로 바꾼다.
 * Step1은 `URL.createObjectURL(file)`을 쓰므로 blob: 스킴으로 구별할 수 있다.
 */
async function syncPendingImages() {
  if (imageUploading.value) return
  const pending = images.value.filter(
    (img) => img.imageUrl.startsWith('blob:') && !syncedImageIds.has(img.id),
  )
  if (pending.length === 0) return

  imageUploading.value = true
  imageError.value = ''
  try {
    for (const item of pending) {
      // 처리 시도 자체를 기록한다 — 실패해도 다시 집지 않는다(재시도는 사용자가 다시 고르는 것)
      syncedImageIds.add(item.id)
      const response = await fetch(item.imageUrl)
      const blob = await response.blob()
      const file = new File([blob], 'product-image', { type: blob.type })
      const uploaded = await uploadProductImage(file)
      const target = images.value.find((img) => img.id === item.id)
      if (target) target.imageUrl = uploaded
    }
  } catch (caught) {
    imageError.value = `사진을 올리지 못했어요 — ${toApiError(caught).message}`
  } finally {
    imageUploading.value = false
  }
}

watch(images, () => void syncPendingImages(), { deep: true })
