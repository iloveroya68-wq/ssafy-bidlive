# ADR-0001: SFU 직접 구현 대신 OpenVidu 사용

- 상태: 승인됨
- 결정일: 2026-07-27

## 배경

이 프로젝트는 6주 안에 라이브 방송과 실시간 입찰이 동작하는 비공개 비크리 경매
서비스를 완성해야 한다. 프로젝트의 목표는 미디어 서버 엔진 연구가 아니라 안정적으로
시연 가능한 사용자 서비스를 구현하는 것이다.

다자간 실시간 미디어 전송을 위해서는 시그널링, SDP와 ICE 처리, NAT traversal,
STUN/TURN 연동, RTP/RTCP 처리, 트랙 포워딩, 대역폭 제어, 패킷 손실 대응, 코덱
호환성 및 참가자 연결 관리가 필요하다. 이를 C++ 기반 SFU로 직접 구현하고 제한된
기간 안에 안정성까지 검증하면 핵심 경매 기능보다 미디어 엔진 개발에 대부분의
시간을 사용하게 될 위험이 크다.

## 결정 요인

- 6주라는 제한된 개발 기간
- 라이브 경매 서비스의 기능 완성도
- 다자간 방송의 시연 안정성
- 팀의 WebRTC 미디어 엔진 구현 경험
- 세션과 참가자 관리 기능의 개발 비용
- 미디어 엔진보다 경매 흐름과 사용자 경험에 집중할 필요

## 검토한 대안

### C++ 기반 SFU 직접 구현

미디어 전송 로직을 세밀하게 제어하고 SFU 내부 동작을 깊이 학습할 수 있다. 그러나
구현과 검증 범위가 현재 프로젝트 기간을 초과하며, 네트워크 환경과 브라우저별
호환성 문제로 서비스 전체의 일정과 시연 안정성을 저해할 가능성이 높다.

### OpenVidu 사용

검증된 WebRTC 플랫폼의 세션, 참가자 및 스트림 관리 기능을 활용할 수 있다. 팀은
SFU 내부 구현 대신 인증, 권한, 라이브 경매 흐름 및 사용자 기능에 집중할 수 있다.
반면 플랫폼 내부 동작과 미디어 전송 로직을 직접 제어하는 범위는 제한된다.

## 결정

다자간 라이브 방송을 위해 SFU를 직접 구현하지 않고 OpenVidu를 사용한다.

OpenVidu는 외부 기술로 취급하며 관련 SDK 호출과 전용 타입은
`media.infrastructure.openvidu` 내부에 격리한다. `api`, `application`, `domain`
계층에는 OpenVidu SDK 타입을 노출하지 않고, `media.application.port.out`에 정의한
포트를 통해 세션 생성, 참가 토큰 발급 및 세션 종료 기능을 사용한다. 다른 도메인은
OpenVidu adapter를 직접 참조하지 않고 media 도메인이 공개한 application 계약을
사용한다.

이번 결정은 OpenVidu의 구체적인 버전, 에디션, 배포 토폴로지 또는 서버 사양까지
확정하지 않는다. 해당 항목은 배포 환경과 부하 목표가 정해진 후 별도로 결정한다.

## 긍정적 영향

- 제한된 기간 안에 다자간 라이브 방송 기능을 구현할 가능성이 높아진다.
- 팀이 경매 상태, 입찰, 인증 및 사용자 경험 구현에 집중할 수 있다.
- 세션과 참가자 관리 기능을 직접 개발하는 비용이 줄어든다.
- SFU 직접 구현에 따른 일정과 시연 실패 위험이 감소한다.
- OpenVidu 연동을 infrastructure에 격리하여 상위 계층의 기술 결합을 제한할 수 있다.

## 부정적 영향

- SFU 내부 동작과 미디어 포워딩 정책을 완전히 제어할 수 없다.
- OpenVidu의 API, 동작 방식 및 릴리스 정책에 영향을 받는다.
- HTTPS, 방화벽, TURN, 네트워크 포트 및 서버 자원을 포함한 배포 구성이 필요하다.
- 장애 분석 시 애플리케이션뿐 아니라 OpenVidu와 네트워크 계층도 함께 확인해야 한다.
- 향후 다른 미디어 플랫폼으로 변경할 경우 adapter 구현과 운영 구성을 교체해야 한다.

## 후속 조치

- 방송 유스케이스에 필요한 OpenVidu 포트를 `media.application.port.out`에 정의한다.
- OpenVidu SDK와 전용 예외를 `infrastructure.openvidu` 밖으로 노출하지 않는다.
- 세션 생성, 참가 토큰 발급, 참가자 조회 및 세션 종료의 실패 정책을 정의한다.
- 로컬·개발·배포 환경별 HTTPS, TURN, 방화벽 및 포트 요구사항을 문서화한다.
- 예상 동시 방송 수와 방송별 참가자 수를 기준으로 부하 시험 계획을 수립한다.
- OpenVidu 장애 시 라이브 경매의 시작, 진행 및 종료 처리 정책을 정의한다.

## 재검토 조건

다음 조건 중 하나가 발생하면 이 결정을 재검토한다.

- OpenVidu가 요구 성능이나 동시 접속 목표를 충족하지 못한다.
- 라이선스나 운영 비용이 프로젝트 제약을 초과한다.
- 필요한 미디어 제어 기능을 OpenVidu가 제공하지 않는다.
- 프로젝트의 목표가 서비스 구현에서 SFU 엔진 연구·개발로 변경된다.
- 플랫폼 장애나 종속성이 서비스 안정성에 허용할 수 없는 영향을 준다.
